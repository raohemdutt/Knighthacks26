1The ceiling the chip allows, against what each build achievesmeasured

The memory on this chip could feed the 27B teacher about 13 tokens a second; our best build so far reaches 2.88, about 21% of what the memory allows, so the gap is in the software, not the silicon.

21%
of the ceiling: 2.88 of about 13.4 tokens a second at batch 1
lab/refine/metrics.jsonl:24 · gpu: Radeon 8060S (Strix Halo), gfx1151 · derived: 100 x achieved tok/s / ceiling tok/s · low confidence

The ceiling is 207.8 GB/s (the chip sheet's copy over its largest buffer, bytes read and written) divided by 15.5 GB of weights read for each token (an estimate): 13.4 tokens a second at batch 1.

The llama.cpp Vulkan prior (14.3) sits above the ceiling. The prior is a fit to 7821 published rows (typical error a factor of 1.38) and the ceiling rests on an estimate, so the two agree within the fit's own error.

2The batching frontier: joules per token against concurrent streamsmeasured

Serving 64 conversations at once instead of one cuts the energy for each word by 18.9 times: the chip draws about the same 96 watts either way and turns out 19 times as many words.

Ruled out before any run (8)

  • PYTORCH_ALLOC_CONF expandable_segments
    compiled out on ROCm in torch 2.9.1, a no-op (note section 3)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:188
  • TF32 (allow_tf32, set_float32_matmul_precision, HIPBLASLT_ALLOW_TF32)
    the step is bf16 and TF32 is not supported on ROCm by default (note section 8)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:189
  • optim adamw_torch against adamw_torch_fused
    LoRA's optimizer step is a small share; fused is already the default from torch 2.8 (note section 11)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:190
  • dataloader_num_workers, pin_memory, persistent_workers
    batches are a few kilobytes of token ids; TS15 checks it is a no-op (note section 10)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:191
  • GPU_MAX_HW_QUEUES and other HIP or HSA runtime variables
    TS2 checks they are no-ops for a single-stream training step (note section 2)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:192
  • MIOPEN_FIND_MODE
    only the torch conv path reaches MIOpen and its share is small; pinned to NORMAL, TS11 checks it (note section 7)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:193
  • use_kernels=True with the Atlas-Inference/gdn hub layer
    third-party code with no documented backward pass; TS8 probes it first (note section 6)
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:194
  • max_length
    a data choice owned by L3, not a speed setting
    lab/refine/research/kernels/data/searchspace-training-gfx1151.json:195
